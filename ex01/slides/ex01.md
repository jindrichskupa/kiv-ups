# Tahák - pojmy

| pojem | IPv4 | IPv6 |
|-------|------|------|
| adresa | 32 b, `192.168.1.42` | 128 b, `2001:db8:1::42` |
| maska / prefix | `/24` = `255.255.255.0` | `/64` (téměř vždy) |
| loopback | `127.0.0.1` | `::1` |
| jen lokální linka | `169.254.0.0/16` (nouzová) | `fe80::/10` (vždy přítomná) |
| privátní | `10/8`, `172.16/12`, `192.168/16` | `fd00::/8` (ULA) |
| IP → MAC | ARP (broadcast) | NDP (multicast, ICMPv6) |
| automatická adresa | DHCP | SLAAC (z RA routeru) nebo DHCPv6 |

<small>Pozn.: MAC = adresa karty v lokální síti (L2), IP = adresa v celé síti (L3), port = aplikace (L4). Co není v mé síti (podle masky), jde na výchozí bránu. Dokumentační adresy pro příklady: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` a `2001:db8::/32`.</small>

# Příklad 3 - zápis IPv4 adres a masek

- a) Převeďte masku: `/20`, `/27` → tečkový zápis; `255.255.252.0`, `255.255.255.248` → prefix
- b) Zapište binárně: `192.168.1.42`, `10.0.0.255`
- c) Které zápisy jsou neplatné nebo podezřelé? `192.168.1.256`, `255.255.253.0` (jako maska), `10.1.2`, `010.0.0.1`
- d) Kolik adres a kolik počítačů se vejde do `/24`, `/26`, `/30`?

---

# Řešení 3

- a) `/20` = `255.255.240.0`, `/27` = `255.255.255.224`; `255.255.252.0` = `/22`, `255.255.255.248` = `/29`
- b) `11000000.10101000.00000001.00101010`, `00001010.00000000.00000000.11111111`
- c) `256` > 255; maska `253` = `11111101` nemá souvislé jedničky; `ping 10.1.2` → `10.1.0.2`, `ping 010.0.0.1` → `8.0.0.1` (!)
- d) `/24`: 256 adres, 254 počítačů; `/26`: 64 / 62; `/30`: 4 / 2

<small>Pozn.: počet počítačů = 2^(32 − prefix) − 2 (adresa sítě a broadcast). Zkrácené a nulou začínající zápisy přijímá stará funkce `inet_aton()` (ping, telnet): chybějící oktety doplní zprava, úvodní 0 = osmičková soustava. V semestrálce adresy validujte striktně.</small>

# Řešení 5

<style scoped>table { font-size: 16px; }</style>

| adresa | typ | dosah | IPv6 |
|--------|-----|-------|------|
| `127.0.0.1` | loopback (`127.0.0.0/8`) | tento počítač | `::1` |
| `169.254.13.7` | link-local (nouzová, DHCP selhal) | lokální linka | `fe80::/10` |

|--------|-----|-------|

# Příklad 7 - ping a TTL

```
$ ping -c 3 192.0.2.80
64 bytes from 192.0.2.80: icmp_seq=1 ttl=57 time=14.2 ms
64 bytes from 192.0.2.80: icmp_seq=2 ttl=57 time=13.9 ms
64 bytes from 192.0.2.80: icmp_seq=3 ttl=57 time=14.5 ms
3 packets transmitted, 3 received, 0% packet loss, time 2003ms

$ ping fe80::3e84:6aff:fe12:3456
ping: connect: Invalid argument
```

- a) Co znamená `ttl=57`? Kolik routerů je asi mezi námi? (Linux posílá s TTL 64, Windows 128.)
- b) Je `time` doba cesty tam, nebo tam a zpět?
- c) Ping na server neprojde, ale web na něm funguje. Jak je to možné?
- d) Proč selhal ping na link-local adresu brány? Jak to opravit?

---

# Řešení 7

- a) `64 − 57 = 7` routerů
- b) tam **a zpět** (RTT)
- c) ping = ICMP, web = TCP 80/443 → firewall může ICMP zahazovat
- d) link-local adresa je na každém rozhraní → chybí rozhraní: `ping fe80::3e84:6aff:fe12:3456%enp0s3`

<small>Pozn.: výchozí TTL se odhaduje jako nejbližší vyšší z 64 / 128 / 255 (např. `ttl=121` → Windows, `128 − 121 = 7`). V IPv6 se TTL jmenuje Hop Limit. "Ping nejde" ≠ "stroj neběží". Windows zapisuje rozhraní číslem: `fe80::…%12`.</small>

# Řešení 8

# Příklad 10 - chat přes `nc` a `tcpdump`

- Ve dvojicích: PC A `nc -l 4242`, PC B `nc <IP A> 4242`, napište `Ahoj!` a Enter. Na A současně `sudo tcpdump -i enp0s3 -nn port 4242`.

# Řešení 10

- klient `192.168.1.20`, efemérní port `51544`; server `192.168.1.42:4242`
- řádky 1-3: 3-way handshake `SYN` → `SYN-ACK` → `ACK`
- řádek 4: data, `length 6` = `Ahoj!` + `\n`
- řádek 5: `ack 7` = "mám bajty 1-6, čekám 7."
- řádky 6-8: `FIN` z obou stran + `ACK`
- IPv6: `IP6 2001:db8:1::20.51544 > ...` - TCP část je stejná

<small>Pozn.: `seq` je u SYN absolutní, dál tcpdump ukazuje relativní čísla (absolutní: `-S`). SYN i FIN spotřebují jedno pořadové číslo. Obsah paketů ukáže `-A` (ASCII) nebo `-X` (hex). `nc` je ideální na ruční test serveru i na posílání nevalidních zpráv: `printf 'KIVUPS...' | nc server 4242`.</small>

# Řešení 11

- a) `ip r` - je tam `default`? → `traceroute 8.8.8.8` - kde se cesta zastaví?
- b) chyba v DNS → `resolvectl status`, `dig @8.8.8.8 seznam.cz` (jde → vadný nastavený DNS server)
- c) DHCP selhal → `sudo dhclient -v enp0s3`, `tcpdump port 67 or port 68`
- d) fyzická vrstva: kabel, port switche, vypnutá karta (`ethtool enp0s3`)
- e) nepřišlo RA → v síti není IPv6 router (nebo RA blokuje switch); `ip -6 r` nemá `default`

<small>Pozn.: postup vždy zdola - **link → adresa → brána → internet → DNS → aplikace**. Ping brány jde i bez výchozí cesty (brána je v lokální síti). `169.254.x.x` si počítač přidělí sám, když nedostane odpověď od DHCP. Zachycení RA: `sudo tcpdump -nn icmp6`.</small>

# Příklad 12 - semestrálka se nepřipojí

- Klient na PC B se připojuje na server na PC A, port 4242. Co znamená která chyba a co ověříte?
	- a) `Connection refused` (okamžitě)
	- b) `Connection timed out` (po desítkách sekund)
	- c) `No route to host`
	- d) spojení se naváže, ale server "nic nedostane"
	- e) přes `localhost` to jde, přes IPv4 adresu ne, přes `::1` taky ne
- Které příkazy spustíte na A a které na B?

# Řešení 12

- a) RST → na `IP:4242` nikdo neposlouchá → na A `ss -tlnp | grep 4242`
- b) žádná odpověď → firewall nebo špatná IP → na B `nc -zv A 4242`, na A `tcpdump port 4242` (chodí SYN?)

- d) síť OK, chyba v protokolu → `tcpdump -A port 4242`: chybí `\n`, `flush()`, špatný formát

# Příklad 14 - DHCP: výpis `ip -4 a` a zachycení (bonus)


# Příklad 15 - výpis `ip -6 a` a `ip -6 r` (bonus)
<!-- bonus -->

```
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 state UNKNOWN
    inet6 ::1/128 scope host
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 state UP
    inet6 2001:db8:1:0:5d2e:91c4:7b1a:3f02/64 scope global temporary dynamic

```
```
2001:db8:1::/64 dev enp0s3 proto ra metric 100
fe80::/64 dev enp0s3 proto kernel metric 256
default via fe80::3e84:6aff:fe12:3456 dev enp0s3 proto ra metric 100
```

- a) Kolik IPv6 adres má `enp0s3`? Která funguje jen na lokální lince?

# Řešení 15
<!-- bonus -->

<small>Pozn.: SLAAC - router posílá RA s prefixem `/64`, počítač si spodních 64 bitů dopočítá sám (EUI-64 nebo náhodně). DHCPv6 je alternativa, kdy adresu přiděluje server; DNS server může přijít v RA (RDNSS) nebo z DHCPv6.</small>

# Shrnutí

- MAC = lokální síť, IP = celá síť, port = aplikace
- co není v mé síti, jde na výchozí bránu; vybírá se nejdelší prefix
- IPv6: `::1`, `fe80::/10`, `2000::/3`, zkracování `::` jen jednou; SLAAC/RA, NDP místo ARP
- `ip a`, `ip r`, `ip neigh` (+ `-6`) / `ipconfig /all`
- `ping` (RTT, TTL / Hop Limit), `traceroute` (rostoucí TTL)
- `ss -tlnp`: `0.0.0.0` / `::` ≠ `127.0.0.1` / `::1`!
- `nc` + `tcpdump` = ruční test serveru a pohled na drát
- diagnostika zdola: link → adresa → brána → internet → DNS → aplikace
